Dexla: from a logo to a system.

Dexla is an AI-powered no-code app builder. When I joined, the brand was a logo. By the time we shipped, it was a style guide, a component library, editor components and Notion documentation written alongside engineering.

01 · Context

Day one was a logo.

Dexla was scaling fast and every new screen restarted the same debates. Typography, colour, spacing and controls were decided case by case. Toba and I built the system together, and the hard part was less the visuals than getting agreement.

02 · Problems

Three things the system had to fix.

  1. P.01
    No shared vocabulary

    No canonical button, no spacing scale, no named tokens. Every cycle re-argued the same decisions.

  2. P.02
    The brand was a logo

    Beyond the mark, type, colour and spacing lived in whichever file shipped last.

  3. P.03
    The builder multiplied drift

    Dexla builds apps, so any drift at the system layer spread into every app a customer shipped.

03 · Process

What we built, and in what order.

The style guide came first: a type ramp, colour, spacing and named tokens, things that could be agreed in a room and referenced in a comment thread. Atomic Design gave us the structure to grow into.

The component library followed, ordered by frequency of use rather than taste: buttons, inputs, modals, navigation, cards. A button decision touches more screens than a tooltip decision.

The no-code editor needed its own pass. The same control had to behave in two contexts: ours, where the system is authoritative, and the customer’s, where it is a starting point they can customise without losing what makes the output recognisable.

Documentation lived where engineering already worked. Each component got a Notion page, and each token a name and a reason.

In closing

Dexla went from a logo to a working system: a style guide, a component library, editor components that let customers customise without breaking the brand, and Notion documentation where every component page points to its named tokens. Design and engineering finally argued from the same vocabulary.
