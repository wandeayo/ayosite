# 404 page: Claude Code handoff

Only the 404 page needs building. The rest of waande.com is live, so reuse its tokens, fonts, header, theme toggle and footer. Don't change any other page.

**Source of truth:** `reference/404.html`. Open it in a browser before writing code. Match it exactly and copy every string from it. If this brief and the file disagree, the file wins.

## 1. Where it goes

- **Next.js App Router:** `app/not-found.tsx`. For other frameworks, use the framework's not-found route.
- **Status:** the page must return a real 404 status, not a 200.
- **Indexing:** `noindex`, with the title "Not Shipped · Ayowande Olubo".
- **Chrome:** use the existing header (name and theme toggle) and footer components. Don't use the inlined copies in the reference file.
- **Floating nav:** don't show the floating nav pill on this page. Its job is done by the terminal links.

## 2. Structure

The page uses the site's 880px column.

1. **Hero**
   - Label: "Error 404 · Not shipped".
   - H1: "I designed this page." followed by a muted span, "I just never shipped it."
   - Lede: names the requested path in an inline code chip.
2. **Canvas** (`.stage`)
   - 16:9 on desktop, 4:5 under 640px. Dotted grid background, radius 16, inset 1px `--line`.
   - Top-left mono readout: "Page 404 · 100%".
   - **Design view:**
     - A frame at 62% width (84% on mobile), aspect 1440:860, containing:
       - Skeleton blocks: a nav bar, a heading and three cards.
       - A huge faint mono "404".
       - Blue selection handles.
     - Labels on the frame:
       - Top tag: "Frame · {path}".
       - Bottom tag: "1440 × 404".
     - Comment pin (orange "AO" avatar): "Still on my to-do list." with the meta line "Ayo · just now".
     - Multiplayer cursor: orange `#e2603a` arrow with an "Ayo" name label.
   - **Terminal view:** a dark window with a bar reading "~/waande.com", and a mono log.
3. **Actions**
   - Primary "Ship it anyway" button. It reads "Back to the canvas" once run.
   - Secondary "Take me home" button.
   - A hint: "or press S", hidden on mobile.

## 3. Behaviour

- **Path**
  - Read it from the request: `usePathname()` or the router.
  - Truncate to 40 characters with "…".
  - Render it as text only. Never as HTML.
  - It appears in the lede chip, the frame tag and the terminal.
- **Cursor loop**
  - The cursor moves between four points on the canvas: (30%,32%) → (62%,46%) → (44%,70%) → (76%,20%).
  - Each move takes 1.3s with `cubic-bezier(.45,0,.2,1)`, followed by a 1.5s pause.
  - At the last point the comment pin pops in for 2.6s.
  - The loop runs only while the canvas is at least 30% in view.
- **"Ship it anyway"** (click, or the S key when no modifier is held and focus isn't in a text field)
  1. The design view cross-fades to the terminal (.45s).
  2. The command `ship {path}` types out at 38ms per character with a blinking caret.
  3. The log then prints these lines, with pauses of roughly 350, 650, 800, 300, 700 and 250ms:
     - `▸ exporting frame from Figma…` (muted)
     - `▸ building route {path}…` (muted)
     - `✕ build failed: frame is empty` (red)
     - `0 components · 0 copy · 1 very optimistic designer` (muted)
     - `↳ nothing to ship here. try one of these instead:` (green)
  4. Four link lines appear, 160ms apart: Home (`/`), Carmen (`/work/carmen-ai`), Airstride (`/work/airstride`), About me (`/about`).
     - Use the site's router links, not full URLs.
  5. Focus moves to the first link. The button becomes "Back to the canvas", which resets the page and restarts the loop.
- **Reduced motion:** no cursor, the pin is shown statically, there are no transitions, and the terminal prints instantly.
- **Accessibility:**
  - The terminal log is `aria-live="polite"`.
  - The decorative canvas parts are `aria-hidden`.
  - The canvas has an aria-label.
